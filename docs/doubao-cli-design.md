# Doubao CLI 接入

## 范围

默认执行任务仍调用原版 Doubao CLI 的公开自动化入口。模型目录通过版本限定的隔离副本读取；正文流式另由用户显式开启实验桥。两种桥都只修改 Calli 临时运行副本的输出，不改原安装、原生配置、凭据或会话文件，也不接管或停止共享服务。验证版本为 **2.31.2，Linux x64**。

本机 CLI 2.31.2 未找到 ACP / app-server 入口，也不接受 `--output-format`。原生包内部有 `json` / `stream-json` 打印器，公开 CLI 任务入口实际固定使用 `text`。流式桥启用副本中已有的 `stream-json` 打印器，并转发原生工具快照；这是 **Calli 的版本限定桥接，不是原生 ACP 支持**。

## 使用

1. 按 Doubao CLI 当前发行说明在主机上安装，先用 `doubao login` 完成登录。官方公开 npm 包是 `@bytedance/doubao-cli`，不要与另一个同名 `doubao-cli` 项目混淆；CLI 不随 Calli 安装。
2. 新安装的 Calli 自带 `doubao` 实例，默认从 PATH 找命令；`CALLI_DOUBAO_BIN` 可覆盖可执行文件。
3. 已有 `agents.json` 不被覆盖。从 Agent 管理的添加入口发现已装 CLI，或者将下面的实例加入原有数组：

```json
{ "id": "doubao", "adapter": "doubao", "command": ["doubao"] }
```

Calli 的发现规则同时识别 `doubao2`、`doubao-2` 等数字后缀，不把 `doubao-helper` 等工具当成实例。管理页的「登录」只在网页终端里运行原生 `doubao login`，不自行实现登录，也不保存凭据。

网页输入区现在可以选择该账号真实可用的模型，并按模型显示推理强度；选择「默认」仍交给 CLI。需要固定实例默认设置时，也可在实例命令中携带当前 CLI 接受的 `--model` / `--effort`：

```json
{
  "id": "doubao",
  "adapter": "doubao",
  "command": ["doubao", "--model", "原生模型 ID", "--effort", "high"]
}
```

模型 ID 和支持的强度来自原生模型加载函数，与原生终端 `/model` 同源。网页选择和实例命令都不会改写 Doubao 的全局设置；Calli 不为了获取目录向模型发送探测问题。实例 `env` 合并进每个原生进程，配置好的用户目录同样用于终端登录和恢复命令；未实现账号发现、独立账号复制或隔离向导。

## 模型目录与切换

- `modelCatalog: true`；沿用网页已有模型/强度选择器，不按 Doubao 名字分支。未开放图片或额外能力。
- 原生公开 CLI 没有模型列表命令。目录桥复用流式桥的 manifest、SHA-256、普通文件/路径校验，复制约 106 MB 的发行运行文件，只在副本中把 `--list` 分支改成调用原生只读模型加载函数，输出模型选项。它不读取历史列表、不创建会话、不调用发送入口、不报告选择记忆；这不是原生 ACP 支持。
- 返回账号实际可用的模型、默认项和该模型可调整的强度；需要升级套餐的模型不作为可选项。`none` 映射网页的 `off`，发任务时再映射回 `none`。没有强度设置的模型返回空列表；切到它时清除旧强度覆盖。
- 每个实例独立缓存 60 秒，并合并并发读取；显式刷新重新查询。失败不会缓存成空列表或替换上次成功的缓存；界面已有错误入口会直接显示失败。版本、结构或未知强度不兼容时明确报错，仍可沿用原生 CLI 默认执行任务。
- 目录进程只带包装器参数和 `--list`，不继承命令中已有的提示词、会话、工作目录、模型、强度或权限业务参数。实例模型默认覆盖会在取得目录后标记，不写全局配置。
- 原生目录进程可能自动启动共享服务；服务校验运行副本的可执行文件身份。读取完成后通过 Linux `/proc` 只读确认该副本的进程已自行退出，再返回并清理副本，避免紧接着用原版 CLI 发消息遭遇身份校验错误。不停止共享服务；15 秒内仍未退出则报错并保留副本，不删除活跃文件。若其他原生 CLI 正在使用不同安装副本，共享服务可能拒绝目录查询；此时不要退出其他人的任务，稍后重试。
- 目录输出有 1 MB 上限，查询进程超时 30 秒，SIGINT 后最多再等 5 秒，只清理本次所属进程组。正常与错误路径都等待管道关闭；副本进程退出后删除临时运行文件，不复制配置或凭据。
- `modelSwitch: true`；切换模型/强度只更新下一轮原生参数，不中断当前任务。下一轮继续带同一个 `--resume`；回到默认由现有线程管理器重建句柄并续接同一 ID。重启后选择仍保存在 Calli 线程记录中。

参考：pi 的 `ModelRegistry.getAvailable()` / 刷新快照与 Open WebUI 的模型目录权限筛选；采用真实可用目录与实例缓存，不写死厂商模型名。

## 开启实验流式桥

默认关闭。推荐在页面设置，无需手改 `.env` 或 Doubao 源码：

1. 在「配置 → Agents → 添加 agent」选择 Doubao CLI，开启「启用实验流式桥」，再点「接入 CLI」。主机上需先安装并登录原版 CLI；没有原生入口时会显示安装命令。
2. 已有 Doubao 实例可从该行的「操作 → 接入设置」开启或关闭。添加页选择已有实例时只更新设置，不创建重复实例或独立账号。
3. 从发现入口接入其他 CLI 副本时，实例选择和流式同意是两个独立开关；新接入默认不选流式桥。
4. 开启时只读检查版本、平台、输出文件校验值与补丁位置，不启动模型、不创建会话、不复制运行包。实际首轮仍会做完整运行文件校验。
5. 开关保存到 Calli 自己的 `agents.json`，由适配器写成实例 `env.CALLI_DOUBAO_STREAM: "1" / "0"`，前端只按适配器能力和返回的开关状态绘制，不识别或构造厂商环境变量。关闭的实例明确覆盖全局开启值；保存失败不生效。
6. 对正在运行的任务不打断。下一轮关闭旧句柄、用新设置恢复同一个原生会话，不需要重启 hub。

也可使用全局环境变量：

```text
CALLI_DOUBAO_STREAM=1
```

也可只为某个实例开启，不影响其他 Doubao 实例：

```json
{
  "id": "doubao",
  "adapter": "doubao",
  "command": ["doubao"],
  "env": { "CALLI_DOUBAO_STREAM": "1" }
}
```

- 只支持已验证的 **2.31.2 / Linux x64**；版本、原生文件或 JS 输出结构校验不通过就停止，不退回最终文本模式，也不重发用户任务。
- 从这个实例的 PATH / HOME / XDG_DATA_HOME 找原生安装；直接指定原生可执行文件也支持。自定义启动包装器可用 `CALLI_DOUBAO_RUNTIME` 指向含 `manifest.json` 的原生运行目录，不复制或另配凭据。
- 按原生 manifest 只复制发行运行文件，逐文件核对大小和 SHA-256；不使用硬链接，不复制配置、密钥、会话、日志或清单外文件，也不下载额外运行包。复制完成后，只在副本中切换输出格式并转发工具快照。
- 每个 Calli 会话句柄保留一份约 **106 MB** 的私有临时运行副本，多轮复用。句柄关闭、归档或 daemon 正常退出时，等待所属 CLI 进程退出后移除副本。daemon 被强制终止时，可能留下可手动清理的临时副本；不包含复制的账号凭据。
- 诊断的协议字段标为 `doubao stream-json bridge (experimental)`，不把它标成 ACP。通过页面关闭开关后，下一轮恢复普通 `-p` 最终文本方式，现有原生 session ID 可继续使用；直接修改 `.env` 需让 daemon 重新读取环境。

## 执行与会话

每轮启动一个进程：

```text
doubao -C <线程目录> --permission-mode ask_risky [其他原生设置] [--resume <原生会话ID>] -p <完整提示词>
```

- 提示词作为一个独立 argv 参数，不经 shell；工作目录同时是进程 cwd 和 `-C`。实例命令里重复的提示词、目录、会话及权限选项被替换，模型/强度在无覆盖时保留。
- 未开桥时 stdout 是助手的**最终回复**，按实际收到的字节输出统一 `message.delta`；这不是 token 流式能力。stdout 中像 JSON 的文本仍是回答。
- 开桥后，`stream_event.content_block_delta` 实时映射 `message.delta`，原生工具快照映射 `tool.start/end`；`assistant` 和 `result` 中的最终正文只补全/修正已流式输出的尾部，不重复追加回答，也不抹掉工具前的中途说明。断流、JSON 结构错误、缺最终 `result`、拒绝操作或取消都不会冒充成功。
- 未开桥时从 stderr 的 `{"type":"session","session_id":"…"}` 读取原生会话 ID；开桥时从 JSON 记录的 `session_id` 读取。支持跨块、CRLF 和最后没有换行的记录，ID 始终按字符串保存，不转换为可能损失精度的数值。
- `start()` 只建立 Calli 会话句柄，首次真实提示词才创建原生会话。收到 ID 即通过 `StartOptions.onSessionId` 保存并广播；空句柄不把线程的 ID 写成空字符串。后续每个进程带 `--resume`，daemon 重启沿用同一 ID。
- 原生返回不同 ID 时停止并报错，不能静默换会话；成功退出但没有会话 ID 或没有回复也不算成功。错误保留有界的 stderr 说明，不将控制记录当作助手回答。
- stdin 使用空输入设备。真实 CLI 会在启动阶段拒绝已关闭的 pipe；空输入不会给更新或登录提示自动作答，也不会一直等待输入。
- 停止发送 SIGINT，由 npm 启动器转给原生进程；五秒后还没退出，只清理这个进程的独立进程组。等待输出管道关闭后才释放当前轮次，不停止共享服务或其他实例。真实验证停止后还能用同一 ID 继续。

## 能力边界

| 能力 | 当前处理 |
|---|---|
| 权限 | 默认「帮我批准」对应 `ask_risky`；无需批准的操作自动执行，需要批准的操作由 CLI 拒绝。完全访问显式使用 `--dangerously-bypass-approvals-and-sandbox`。无「请求批准」档位 |
| 模型/强度 | 版本限定目录桥返回真实可用模型、默认项和每模型强度；网页可选择/切换，下一轮生效。目录失败直接报错，登录有效性仍由实际请求检查 |
| 正文与工具 | 默认最终文本；实验流式桥提供真实文本增量和原生工具开始/结束。原生 generic 工具可能只有标题与结束信号，不带输入/结果；缺失字段不猜测，工具结果标为未知，不当作成功 |
| 思考、用量 | 本桥未接入，不根据正文或进度文字估算思考、上下文、token |
| 协作与交接 | `sessionEnvironment` 传递运行时 Calli CLI 和范围凭证，不写配置。假 agent 已覆盖协作、只读交接 CLI；真实 CLI 已核实本地 shell 收到实例环境 |
| 图片 | 未找到公开输入协议，能力关闭。普通文件沿用 Calli 的路径说明，不冒充视觉输入 |
| 计划、目标、压缩 | 未开放，无对应能力；不把 `/compact`、`/goal` 等终端命令当普通模型提示词 |
| 历史、分叉、原生删除 | `--list` 只给 ID 与标题，没有可导入的工作目录/历史回放；不开放导入、终端同步、分叉或原生会话删除 |
| 原生斜杠命令 | 列表为空。直接发送终端命令时明确报错，请在终端恢复会话后使用；Calli 自己的文件、终端、导出等操作照常可用 |

权限语义来自原生 `--help` 与实际执行，不等同于只允许编辑文件；没有人工审批卡时，风险操作不能等待网页上的批准。
