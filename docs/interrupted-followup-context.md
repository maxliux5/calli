# 中断后追问上下文

## 技术方案

停止一轮时，原生 Agent 不一定已保存这次用户请求。之后发送“这个有什么用”等追问，可能失去指代对象。本改动只补充请求文本上下文，不恢复完整原生历史、不重跑旧请求，也不改写原生会话文件。

- 只检查同一线程最近一轮：`turn.done.stopReason = cancelled` 或 `turn.error.code = interrupted` 才符合条件；一般执行错误与正常结束不携带。
- 排除交接、协作控制、导入、终端同步、原生后台回复、后台问题、语音、主动任务、定时任务、评审与隐藏协议请求等来源。
- 下一条请求必须是普通非空消息。斜杠命令、自动续写、定时、评审、交接、协作投递、主动任务与带显式展示文本的内部请求保持原有提示词，不携带旧上下文。
- 发送内容用 `[Calli interrupted-turn context]` 包装前次请求和当前消息，并说明当前消息不相关时只回答当前问题。这里不做语义分类，也不检查原生历史是否确实缺失，因此可能重复已有上下文、增加 token。
- 原始发送内容留在 `turn.started.text`，用户本次输入继续使用主干已有的 `displayText`。后台任务、消息注入门控、协作成员直接回复和已有内部消息展示语义不变。
- 连续中断时优先复用 `followupContextText`，其次读 `displayText`，最后兼容旧事件的 `text`；携带文本只保留末尾 12,000 个 JavaScript 字符串单元，不是 token 上限。正常完成后下一轮不再携带。
- 不额外复制旧附件、工具输出或半截回答。上下文只是模型提示，不保证指代理解结果。
- 包装的公共头部超过历史匹配原来的 200 字限制。仅这种包装请求改用完整文本匹配，避免原生历史漏掉已取消追问时，把后续请求错配到该轮；普通请求保持主干的现有匹配规则。

## 代码修改方案

1. `packages/daemon/src/threads.ts`
   - 增加最近中断轮次的文本提取、长度限制和提示词包装。
   - 在主干现有发送流程内接入，保留 `InjectionGate`、后台问题和 `displayText` 行为。
   - 在 `turn.started` 事件中保存 `interruptedFollowup` 标记和有上限的 `followupContextText`，不新增数据库列。
   - `turnKey` 仅对该上下文包装使用完整文本，不引入其他分叉或同步功能改动。
2. `packages/daemon/test/api.test.ts`、`packages/daemon/test/coordination.test.ts`
   - 区分用户可见文字和实际发送提示词。
   - 覆盖手动停止、立即发送打断、重启中断标记、正常结束后停止携带、连续中断与长度上限。
   - 覆盖一般错误、特殊来源、命令、内部请求不注入，以及公共头部不导致原生历史错配。
3. `packages/daemon/test/fixtures/fake-{pi,acp,agy,doubao}.mjs`
   - 识别该提示词包装，测试行为只由当前请求触发，避免旧请求里的 `slow` 等标记使新追问永远不结束或触发旧指令；保留当前追问自身的慢轮次与其他测试行为。
4. `docs/PLAN.md`、`docs/TODO.md`
   - 同步业务行为和本独立改动的边界。

本改动只包含中断后追问上下文及相关回归，不修改全局权限默认值、压缩历史分叉、图片、自动命名或 native writer 防护。

## 验证范围

- `scripts/init.sh --check`：隔离假 Agent 的构建与冒烟。
- 中断上下文和队列专项 API 回归。
- 提交前按仓库约定执行 `npm run typecheck`、`npm test`、`npm run build`，实际结果记录在 PR。
- 测试使用假 Agent；不以这些回归声称真实模型的上下文理解效果已验收。
