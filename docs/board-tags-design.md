# 看板与标签设计

状态：设计稿，未实现。更新：2026-10-13。

2026-10-19 更新：三列与侧栏「按活动查看」重复，列改为进行中、等你、待验收、已完成，并新增由用户勾选的线程「已完成」标记；不做「已完成」列的决定因此改变：完成仍只由人判定，但对象是线程本身（见 [工作台扩展](extension-workbench-design.md) 开头）。标签部分仍然有效。

后续实现方式更新：看板作为首个内置 Calli 扩展，入口与数据契约见 [工作台扩展](extension-workbench-design.md)。本文保留线程卡片、三列和标签的设计依据；标签单独推进，不再作为只读看板的前提。业务任务视角另按数据源提供，不替代这里的线程视角。

## 核心决定

- **卡片是线程。** 看板覆盖所有未归档的线程，不要求先关联计划项。计划页保留，照旧管理长期目标。
- **列表示「现在要我做什么」，自动得出，不能拖。** 三列：待处理、运行中、空闲。把线程拖到「运行中」并不会启动 agent，所以不提供拖动。
  - 2026-11-10 更新：线程可以由人手动放到某一列（存为 `by: 'user'` 的进度报告，agent 下一轮报告时覆盖），拖动因此等同于手动改状态，已经提供；拖到「进行中」仍然不会启动 agent。运行中或等你处理的线程以实际状态为准，只能拖到「已完成」。
- **标签是可以交叉的主题。** 一个对象可以贴多个，线程、计划项、定时任务都能贴，跨项目。
- **看板和「按活动查看」共用一套状态判定。** 侧边栏是紧凑的入口，看板是展开的呈现。

曾考虑让卡片是计划项，放弃了：大多数线程没有关联计划项，会直接从看板上消失；一个线程又可以关联多个计划项，混排时一张卡片到底是谁说不清。

参考 [Vikunja](https://vikunja.io/features/)（Codex 成员读过功能和标签文档，没有读源码，主控未核对）：同一批任务可以在列表和看板之间切换，标签跨项目筛选。只取一点：视图改变呈现，标签改变筛选，都不制造副本。

## 现有的分组各管什么

加标签之前先把话说清，免得越加越乱：

| 分组 | 表示 | 一个线程能有几个 |
|---|---|---|
| 项目 | 代码在哪个目录 | 一个 |
| 分区 | 侧边栏里收在哪 | 最多一个 |
| 标签（新） | 属于哪些主题 | 多个 |
| 置顶 | 排在前面 | 是或否 |
| 交接链、同题对比 | 线程之间的关系 | 由 hub 记录 |
| 按活动查看、看板 | 换一个角度看 | 不是属性 |

分区不动，已有的整理不受影响。看板主要按项目和标签筛选，分区收进筛选菜单。

## 标签

- 名字去掉首尾空白，同一台机器上不重名。只在当前机器有效，不暗示跨机器同步。
- 颜色只有两档：普通（`--muted`）和强调（`--accent`），底色和边框用已有变量。红和橙留给出错和待审批，不开放任意颜色。标签靠名字辨认，颜色只是辅助。
- 线程的标签和计划项的标签各自独立，不互相继承：一个线程关联两个计划项时，继承谁说不清。唯一的例外是定时任务建出的线程，创建时带上任务的标签（见[长期跟踪](tracking-design.md)）。
- 贴标签的入口：线程菜单、计划项菜单、定时任务表单，都是一个「标签」子菜单，可以勾选已有的或当场新建。管理（改名、换颜色、删除）在「配置」里一页。
- 筛选的入口：侧边栏搜索框旁边、计划页顶部、看板顶部。

## 看板

入口是侧边栏里「计划」旁边的一行，主区域换成看板页，地址 `#/board`，刷新后还在。

### 列

按顺序判断，落进第一个符合的：

1. **待处理**：等审批、出错、有新结果没看，以及跟踪任务这次没查全（见[长期跟踪](tracking-design.md)）。卡片上写明是哪一种。
2. **运行中**：其余正在跑的。
3. **空闲**：其余未归档的。默认只显示最近 30 天动过的，更早的折叠成一行。

「出错」现在不在「按活动查看」的优先级里（`packages/web/src/sidebar.ts` 的 `urgency`），两处共用判定时一起补上。

等待类型按核心当前能力区分审批、回答、计划确认；看板和侧栏共用统一的待处理原因，不将它们都写成「等审批」。

不做「已完成」列：线程跑完一轮不等于任务完成，归档也不等于完成。完成属于计划项，由用户自己勾。不做「定时跟踪」列：定时是运行方式，定时线程同样可能等审批或出错，所以做成徽标和筛选。

### 卡片

正面只放一眼要看到的：

- 标题、项目名、实例标志
- 一行原因：等你批准（几条）、出错（原因）、有新结果、运行了多久
- 最多两个标签，多的显示「+N」
- 徽标：定时、工作树、交接、对比、协作成员数

点卡片进线程。卡片上一个展开按钮，按需加载这些：

- 分支和未提交改动数。要跑 git，而且同目录的线程共享这个数，所以不放正面，标题写「这个目录」而不是「这个线程」。
- 实例的额度档位。来自现有的额度接口，不是每个实例都有。
- 关联的计划项。
- 最后一段回答的开头。

列内排序：置顶在前，其余按最后更新时间。

### 筛选

顶部一行：项目、标签、实例、是否定时。都用 `Popover`，可以多选，选择记在本机。

### 空状态

三列都空时，中间放一只海蛞蝓和一句话。这是它该出现的地方之一。

### 手机

顶部三个页签带数量（待处理 3、运行中 1、空闲 12），下面只显示选中那一列的卡片，默认「待处理」。不让人横着找列、竖着找卡片，也不依赖长按拖动。卡片只留标题、项目和实例、原因、最多两个标签，其余进展开。

## 数据与接口

| 表 | 字段 |
|---|---|
| `tags` | `id`、`name`（唯一）、`tone`（普通或强调）、`created_at` |
| `thread_tags` | `thread_id`、`tag_id`，联合主键，随线程或标签删除 |
| `todo_tags` | `todo_id`、`tag_id`，同上 |
| `schedule_tags` | `schedule_id`、`tag_id`，同上 |

不存列状态，它是算出来的；不建通用的「卡片」表。

| 接口 | 用途 |
|---|---|
| `GET /api/tags`、`POST /api/tags`、`PATCH /api/tags/:id`、`DELETE /api/tags/:id` | 标签的增删改查 |
| `PUT /api/threads/:id/tags`、`PUT /api/todos/:id/tags`、`PUT /api/schedules/:id/tags` | 整体替换某个对象的标签 |
| `GET /api/threads/:id/checkout` | 展开卡片时取分支和未提交改动数 |

线程、计划项、定时任务的现有返回里各加一个 `tags`（标签 ID 的数组）。线程视图再加两个字段：`pendingApprovals`（待审批数，从内存里的审批表汇总）和 `attention`（卡片上那一行原因，由 daemon 给出，前端不自己拼）。标签变化走现有的全局事件流。

`listTodos` 现在逐个计划项查关联、逐个线程构造视图；加标签时改成批量读，不在上面再叠一层逐卡片的请求。

| 文件 | 改动 |
|---|---|
| `packages/daemon/src/store.ts` | 四张表、批量读 |
| `threads.ts`、`http.ts` | 标签接口、两个新字段、checkout 接口 |
| `packages/web/src/sidebar.ts` | 状态判定抽成和看板共用的一个函数，补上出错 |
| 看板扩展包与宿主视图注册（待定） | 看板，走公开契约，不直接在核心添加专用页面分支 |
| `Sidebar.tsx`、`TodosPage.tsx`、线程菜单 | 贴标签、筛选、入口 |

## 分期

1. **只读看板扩展**：三列、线程卡片、项目/实例筛选、手机页签，先验证最小宿主。
2. **标签**：表、接口、贴标签、侧边栏和计划页按标签筛选，单独推进，不阻塞看板。
3. **用过再定**：计划项自己的看板视图（那里才有「待验收」这类用户定义的阶段）；卡片展开里的 git 信息加缓存。

不做：自定义列、任意颜色、标签跨机器同步、把项目和分区也变成标签。

## 验证

标签接口要有测试：重名、删除后关联消失、整体替换。状态判定是纯函数，单元测试覆盖等审批、出错、未读、运行、空闲各一条和它们的先后顺序。界面按 `AGENTS.md` 的要求在真实浏览器里看桌面和手机、亮色和深色。
