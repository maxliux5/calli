# 配置页面与菜单

本轮按已选 Playground 的 B（电脑分类与详情并排、手机逐页进入）和柔和玻璃实现。短菜单沿用所选的锚定浮层方向。Playground 仍是临时验证材料，正式代码不依赖它。

## 参考与取舍

- 用户提供的 Codex 手机截图：配置分组列表、单一页面标题；返回与工具按钮分别使用玻璃材质。截图里的设置本身也有 sheet，因此目标不是禁止所有浮层，而是避免“大容器、整条导航胶囊、按钮”连续套三层。
- [Chatwoot 的配置路由](https://github.com/chatwoot/chatwoot/blob/develop/app/javascript/dashboard/routes/dashboard/settings/settings.routes.js)：配置作为可以定位、返回的页面，适合内容多的设置。
- [Open WebUI 的设置容器](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/SettingsModal.svelte)：按类别组织内容可借鉴；多项配置放在同一个 modal 的承载方式不沿用。
- [LibreChat 的 DropdownPopup](https://github.com/LibreChat-AI/LibreChat/blob/main/packages/client/src/components/DropdownPopup.tsx)：短操作保留在触发位置附近，与完整配置页区分。

## 行为

「配置」占满窗口，隐藏会话侧栏及其拖动分隔线。电脑只保留配置分类与详情，手机先显示分组入口，再进入单个详情；左上角返回逐层回退，离开配置后恢复原会话和侧栏偏好；手机从会话列表进入的配置，关闭后回到列表（从哪来回哪去，参考 LibreChat 与 Lobe Chat，左上角和边缘滑动结果一致）。配置页不响应展开会话侧栏的快捷键或边缘滑动。常规、外观、语言、推送、私人设置、自动交接和机器使用统一页面容器；智能体、团队、技能、MCP、扩展及统计页也从同一导航进入。旧独立页面地址继续可用。归档、历史导入、额度查看进入配置子页，额度账号详情进一步进入下一层；删除确认保留短弹窗。

私人设置先显示目录、智能体和模型，飞书、简报、主动行动、个人资料点击后分别加载和编辑。每个子页只保存本页数据。推送完整记录、机器候选和定时任务运行记录按需读取，加载失败可重试。

统一入口不代表所有子流程已经迁移。技能与 MCP 的详情和安装、外部扩展配置等仍使用弹窗；额度、归档和历史导入已在后续接入统一配置子页。2026-11-06 按实际组件重新核对的范围、后续优先级和额度参考方案见 [额度与配置遗留审查](quota-navigation-review.md)。

定时任务采用同一列表／详情关系。电脑并排查看，手机进入任务后显示单独编辑页。名称和提示词在前，执行配置在后；保存操作固定在底部。

未保存的配置在应用内返回、切换类别、浏览器历史导航时先提示；取消保留编辑状态，保存失败也保留输入。保存中阻止跳走。进入设置前的会话草稿和阅读位置在返回后恢复。刷新页面重新读取已保存配置，不承诺恢复未保存的配置表单。

浏览器历史里属于应用的部分始终只有两条：底部记录和应用当前所在的记录（`appHistory.ts`）。配置的层级、定时任务详情、会话列表都是应用状态，不压历史，所以开关配置多少次也不会留下可以滑回的旧页面，刷新后也不会在栈里留下旧配置页。手机的边缘右滑（系统后退）落到底部记录时，应用执行与左上角按钮相同的一步返回，再立刻把应用记录放回去：先关会话列表，再退一层配置，再关闭配置，在会话或普通页面则打开列表；列表打开时再滑就是关闭。应用自己的边缘滑动刚动过列表时，紧随其后的系统后退算同一次手势，不再处理第二遍（iOS 上同一根手指会同时触发两者）。电脑上没有可撤销的步骤时，把后退交还给浏览器。文件、智能体、轨迹等面板仍在应用记录之上压自己的一条，后退先关它们。从别的页面点进的 `#/settings/…` 链接是普通记录，后退回到点击前的地址。

## 材质与菜单

正文和配置页保持不透明。玻璃只用于返回按钮、会话工具组、输入框、短菜单和固定操作栏。手机顶部不再放一整条带边框的圆角玻璃容器，不重复显示大标题。颜色、边缘高光、阴影和模糊量使用 `styles.css` 顶部变量；不支持背景模糊或系统要求降低透明度时退回实色。这是网页对玻璃材质的近似，不是原生 iOS 的完整折射效果。

上一版填充为 84% 实色，聊天滚动区又止于顶栏和输入框之间，玻璃后面只有空白，因此看不出材质。这次沿用已选方向修正：填充降为 52%，增加斜向反光及内缘高光；聊天滚动区延伸至顶栏与输入框后方。用实际顶栏和输入区域的高度保留首尾阅读空间，队列、附件、多行输入或手机键盘引起高度变化时随之更新；错误及更新提示仍占据正常位置。原生桌面标题区不参与叠放，完整配置页也不加第二层玻璃外壳。

叠放参考 [Open WebUI 的聊天顶栏](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/Navbar.svelte) 的透明导航、负间距及渐隐；阅读空间参考 [LibreChat 的 ChatForm](https://github.com/LibreChat-AI/LibreChat/blob/main/client/src/components/Chat/Input/ChatForm.tsx) 的输入区留白，材质范围继续以用户提供的 Codex 截图为准。没有引入浏览器兼容性受限的 SVG 折射滤镜。

菜单与值选择器共用材质、间距和触摸尺寸；手机也锚定触发位置，长列表内部滚动。支持键盘选择、Escape、视口边界约束，保留长按后防误触。手机子菜单在同一浮层内切换，桌面在旁边展开。

## 验收

`settings-navigation.spec.mjs` 覆盖电脑／手机尺寸、浅色／深色、配置页入口、锚定菜单、保存失败重试、草稿离开确认、浏览器返回、详情按需加载和返回会话，并验证关闭配置后历史栈不再残留：边缘滑动（浏览器前进／后退）不会重新打开配置。原有常规、外观、私人设置、定时任务、技能与 MCP 等浏览器测试同步到新导航。

浏览器验证使用 Chromium；真实 iPhone Safari 的键盘、滚动及玻璃观感仍需真机验收。

`glass-surfaces.spec.mjs` 在电脑／手机、浅／深色验证正文确实经过玻璃控件后方，首尾消息可读，多行输入增高后底部留白同步，短菜单可用，以及降低透明度时退回实色。

2026-11-07 材质修正的类型检查、构建通过，单元测试 1632 项通过、1 项跳过；配置、额度、侧栏、手机键盘和聊天控件等浏览器回归 24 项通过。已查看四组 Chromium 截图；真机 Safari 待验收。

状态栏接缝修正：玻璃顶栏的渐变起点与系统状态栏使用同一实色，覆盖 `safe-area-inset-top` 并继续向下过渡，再逐渐显示模糊背景，避免原来 70% 半透明起点在状态栏下产生横向色差。背景延伸至边缘、按钮仍让开安全区，采用 [WebKit 的安全区指导](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)，连续渐隐沿用 Open WebUI 的导航方式。浏览器回归通过 CDP 模拟 59px 及 0px 顶部安全区，并在强对比背景下比较接缝两侧的实际截图像素；旧渐变能重现失败。手机使用用户截图中的石墨配色，电脑使用纸配色，均覆盖亮／暗主题。

### 线程菜单收敛 A（2026-11-07）

用户在独立 Playground 选择按用途分组的 A。首层为文件、终端、整理线程、复制、分叉与交接、归档／恢复、永久删除，共七项；原动作、能力判断与图标沿用。重命名、重新取名、置顶、未读、分区、计划和电脑轨迹归入整理；分叉、交接、交接记录放在同组。配置和归档列表的同类线程入口使用相同分组，不删除低频功能。

参考 [Open WebUI 的会话菜单](https://github.com/open-webui/open-webui/blob/main/src/lib/components/layout/Sidebar/ChatMenu.svelte) 将相关动作放入子菜单；参考 [CodexBar 的紧凑模式](https://github.com/steipete/CodexBar/blob/main/docs/ui.md) 在概况保留标注读数、将重置和其他细节放在详情。取舍是减少一级内容，手机操作行继续为 46px，电脑为 40px，聊天顶栏高度不变。

额度首层保留主要模型池的双条，点上方摘要进入全部额度查看重置时间、其他周期和模型池。异常概况检查所有返回窗口；低额度、耗尽、繁忙、刷新失败和旧值仍在固定高度的标题区直接提示，不因刷新临时增加一行。首次加载使用与双条相当的占位；失败且无缓存和服务确实未提供读数分别说明，不伪造零值。

手机在同一浮层逐层进入与返回；电脑在根菜单旁保留一块详情菜单，继续进入分区或计划时替换这块内容。Escape／左方向键只返回一层，恢复原触发项焦点；左右方向键和上下选择、外部点击、长按防误触继续可用。长子菜单只在可视区域内滚动，避免跨过屏幕边缘。

验证记录：初始化冒烟、全仓库类型检查、1641 项单测（另 1 项跳过）及生产构建通过。首次全量运行曾遇到既有 Pi effort 用例缺少日志，完整复跑通过；前端最终调整后另跑类型检查和生产构建通过。23 项相关浏览器用例通过，覆盖 320／390／1440 宽度的亮暗主题、手机长按、各层焦点与 Escape 返回、重命名时的流式更新、分区／计划的实际保存、文件与草稿保留、额度首次加载／刷新／失败缓存、跨入口同步、配置和交接记录。中英日长异常标题额外检查了文字范围和固定高度。已查看双端、亮暗及窄屏多语言的实际 Chromium 截图；标准字号首层约手机 464px、电脑 422px，真实 iPhone Safari 待用户验收。

### 列表与线程页菜单分离（2026-11-08）

用户撤销「整理线程」：把杂项再包一层是加深层级，不是精简。列表行菜单与线程页右上 ⋯ 拆成两份，各自只做自己的事。参考 ChatGPT、Claude app 与 Telegram 的会话列表：长按只有行管理（置顶、归档、删除），对话页菜单只有对话工具，没有谁在对话页里再套「整理」子菜单。

列表行（长按／⋯／右键）：置顶、重新取名（自动取名扩展开启时）、移到分区、关联到计划、归档／恢复、永久删除。线程页 ⋯：额度快览（固定表头）、文件、打开终端、置顶／取消置顶、标记为未读／已读、重命名、重新取名（扩展开启时）、复制（Markdown／恢复命令／Session ID／工作目录）、分叉与交接（分叉／交接／交接记录）、轨迹（电脑；手机从概况进）。用户要求把原先在「整理」里的重新取名、置顶、标记为未读连同重命名平铺到 ⋯ 一级，不搬其余杂项，所以移到分区与关联计划留在列表行菜单；归档与永久删除只留在列表；从别的线程行打开它的文件这一隐藏入口取消，文件只从打开线程的 ⋯ 进。斜杠命令的重命名／置顶／分叉／归档不受影响，仍是线程页内的快捷路径。

高度（2026-11-09）：一级动作变多后，手机整菜单约 505px。用户选「收紧行高」：线程页 ⋯ 加 `menu-dense`，行高手机 46→44、电脑 40→36，并去掉两条分隔线，整菜单约手机 452px、电脑 424px；列表行与分区菜单的行高不变，手机 44px 仍满足触控目标。

补平铺（2026-11-09）：用户指出「整理」去掉意味着它里面的项在**两处**都要放出来，不是只在 ⋯。列表行菜单同样平铺：置顶、标记为未读／已读、重命名、重新取名（扩展开启时）、移到分区、关联到计划、归档、永久删除；「⋯」保持上一条的一级布局。行菜单仍不进对话工具（文件、终端、复制、分叉与交接），两边分工不变。
