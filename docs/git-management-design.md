## 参考与取舍

- [Persona GitPanel](https://github.com/nwverse/persona/blob/main/web/src/views/session/GitPanel.tsx)：本地参考版本 `72f6f6be`。会话目录决定仓库，分支、上游同步情况、文件变更、提交记录集中在侧栏；文件差异按打开的条目读取，历史分页。刷新保留已有读数。其首个状态响应也携带近期提交，本版将历史独立到用户打开时读取。
- [Persona Git 后端](https://github.com/nwverse/persona/blob/main/server/internal/node/git.go)：直接执行 Git，不发送一轮 agent 消息。拉取检查仓库、当前分支、上游和未提交修改，只执行快进更新，并显式关闭 rebase、自动 stash 和子模块递归。
- [CloudCLI GitPanelHeader](https://github.com/siteboon/claudecodeui/blob/main/src/modules/git-panel/GitPanelHeader.tsx)：将刷新、fetch、pull 分成不同操作，分支行展示领先与落后数量，操作失败直接可见。借鉴这一区分，首版保留中性色与文字按钮，适配手机点击。

首版采用 Persona 式侧栏，结合 CloudCLI 的 fetch / pull 区分；支持状态、只读差异、提交历史和快进拉取。

## 首版接口边界

入口随当前线程的机器和工作目录，Git 是 daemon 通用能力，前端不按 agent 名字分支。

- 概况：当前仓库与 worktree、分支、上游是否存在、领先／落后数是否已知、未提交文件概要。初始未读取、失败和非仓库是不同状态。
- 文件差异：打开单个文件时读取，区分已暂存和未暂存，返回二进制与截断信息；路径必须来自当前仓库范围，不能通过 Git 对象接口绕过文件授权。
- 提交记录：切到提交记录时才读取并分页；点提交先读文件概要，点文件再读差异。
- 刷新状态：只重新读取本地信息，不执行网络操作。
- 获取远端：显式点击才执行 fetch，更新远端跟踪信息；旧读数保留到成功返回，失败显示旧读数的时间。
- 拉取更新：显式点击才执行，只允许快进；拒绝未提交修改、未跟踪文件、冲突、分叉、无上游和 detached HEAD。执行前重新检查，不能只相信按钮状态。

拉取会检查本 hub 在同一工作区中运行或正在启动的线程；操作按 Git common directory 排斥并发，拉取锁持有期间，同一工作区的新回合会收到忙碌错误。其他 worktree 的 agent 回合继续运行。其他程序的并发修改无法完全控制，仍需依赖 Git 本身的锁与执行前检查。Git 接口已使用真实临时仓库验证。

每次 Git 调用使用参数数组与字面量 pathspec、超时和输出上限；差异限制为 512 KiB / 4,000 行，长内容明确标注截断。关闭外部 diff、textconv 和 hooks，禁止交互式凭据提示；不把远端 URL 中的凭据带到响应。fetch 与 pull 结果更新同一份概况；网络操作结束但状态重读失败时，明确区分操作结果与读数失败。

提交、推送、切分支、stash、撤销修改与 PR 管理另行确定范围，原型不把这些按钮做成可用功能。

## 接口

均位于 `/api/threads/:id/git/`，沿用现有鉴权和多机代理：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `status` | 当前工作区轻量状态，无历史与 diff |
| GET | `log?head=&skip=` | 固定提交锚点，每页 30 条 |
| GET | `commit?commit=` | 指定提交的文件列表；合并提交按第一个父提交比较 |
| GET | `diff?path=&staged=&commit=` | 一个文件的差异或未跟踪文件内容 |
| POST | `fetch` | 获取所有已配置远端，返回更新后的状态 |
| POST | `pull` | 快进拉取，返回是否更新及状态重读结果 |

未提交文件的列表先显示文件状态；增删行与内容在展开差异后读取，概况不额外生成全仓库 diff。
