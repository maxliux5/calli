# 会话、消息与目录引用

用户已选择 A 紧凑版。本分支接入单行引用标签、统一选择器和整条回复引用，保留现有编号注释。

## 参考与取舍

采用 persona 的轻量来源标签与消息引用体验、Cline 的目录选择入口；参考 VS Code 的独立上下文入口。内容按需读取，不预先展开整个会话或递归打包目录。

| 参考 | 实际行为 | 本项目取舍 |
| --- | --- | --- |
| persona：`web/src/lib/mentions.ts` 的 `sessionQuote` | 会话引用带标题、目录、来源 URI，最后一段文字最多 600 个 Unicode 字符 | 借用紧凑标签；补可分页的历史读取，不能将 600 字预览当作整个会话 |
| persona：`web/src/views/chat/MentionMenu.tsx` | `@` 混合文件、目录、会话；目录逐层浏览 | “引用目录本身”和“进入下一级”分别提供按钮，兼顾手机 |
| persona：`web/src/views/chat/Quote.tsx` | 消息引用展示来源与简短预览 | 整条回复沿用已有注释，不另建一套评论协议 |
| [Cline：Working with files](https://docs.cline.bot/core-workflows/working-with-files) | `@` 选择文件、目录，`+` 浏览 | 借用入口；目录内容由 agent 按问题读取 |
| [VS Code：Chat context](https://code.visualstudio.com/docs/chat/copilot-chat-context) | `#` 或 Add Context 添加上下文；附加项目不会成为执行工作区 | 引用目录不切换工作目录 |

## 怎么使用

- 在输入框键入 `@`，或点击 `@` / `+` 内的“引用会话或目录”。可按标题搜索会话，或输入 `~/code/…/` 浏览目录。
- 点击目录名称选择该目录，点击右侧箭头进入下一级；“引用此目录”选择当前浏览位置。
- 会话、目录以一排标签显示，点击查看来源信息，独立关闭按钮移除。
- 回复底部“引用整条回复”将整条正文带入现有注释区，可以继续加评论。
- 协作对象仍是派任务，在同一选择器内单独分组。

## 回复下面的操作栏

用户确认学习 Persona 的消息操作，分叉继续直接显示。除 Persona 的 `MessageActions.tsx` 外，还查看了 [Open WebUI 的回复组件](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/Messages/ResponseMessage.svelte)，采用明确区分动作、按可用能力提供入口的做法。

- **交给助手**：将所选回复带入助手草稿，先补充要求，再发送给主机器的助手。取消、发送失败保留要求，来源会话的草稿不受影响；跨机器传递所选正文快照，不扩大历史读取权限。
- **作为上下文**：把所选正文存成资料快照，输入框展示紧凑消息标签，与引用和编号注释分别保存。元数据与正文分开存储，长正文通过 `calli references ID --offset N` 分块读，不能用消息引用读取其他轮次。
- **复制、引用、分叉**：保留直接操作；分叉不收进三个点。
- **更多、右键、手机长按**：共用复制、引用、交给助手、作为上下文、选择文字菜单。自己的消息仍有编辑按钮，右键菜单也提供编辑。链接、代码和已有文字选区保留原行为；手指移动取消长按。
- **选择文字**：只读纯文本弹层，可复制所选或把所选文字加入原有注释区。

本轮范围为消息操作栏。原生“回退到这里”是另一个能力，当前适配器没有对应接口，尚未实现。

## 与注释兼容

会话与目录作为资料引用，不占用注释编号。整条回复和原有选区、文件注释使用同一个 `Note` 模型；没有评论的整条引用，其 `comment` 为空。

发送仍使用既有 `[注释 N]` / `评论：` 协议，随后是资料引用和用户正文。`<calli-references>` 只携带引用元数据；显示时还原成标签。草稿、排队、撤回排队、重试和消息编辑都保存这些引用。发送失败保留输入，成功后清空。

## 历史与目录读取

`POST /api/context-references` 仅由已认证浏览器创建引用。选择会话只保存标题、路径、来源线程及当时的事件边界；选择目录通过已有目录浏览边界校验并保存真实路径。前端不加载全文。

发送被接受时，服务端将引用的读取权限授予接收线程。agent 使用自己现有的线程凭据调用 `calli references ID`，不能借此读取未附加的来源。

- 默认按轮分页，长答复有 Unicode 字符偏移和下一段命令。
- 工具列表先返回概况；超过概况上限时可继续列出 ID，工具参数和结果单独分块读取。
- 会话固定在选择时的历史边界。来源继续输出不改变已选范围；历史重写或来源删除会明确报错，需重新选择。
- 目录只提供位置，agent 沿用自己的文件工具与原生权限。不改变工作目录、项目根或 agent 配置。
- 引用内容标为参考资料；读取不会唤醒来源会话或向来源发消息。
- 权限与元数据保存在 SQLite，可跨 hub 重启使用。

首版限定当前机器、已接入 hub 的线程和 hub 已同步的历史。未导入的原生会话不会为了引用而被启动；交接前作为独立线程存储的历史需另选对应线程。目录是实时文件位置，并非文件内容快照。

## 接线位置

- `packages/web/src/components/ContextReferences.tsx`：标签、详情、按需选择器。
- `packages/web/src/context-references.ts`：引用协议、草稿恢复与队列预览。
- `Composer.tsx`、`ThreadView.tsx`：输入、发送、编辑、整条回复引用。
- `packages/daemon/src/context-references.ts`：创建、权限、历史分页与目录校验。
- `history.ts`：复用既有交接历史投影，增加可选快照边界。
- `bin/calli`、`bin/calli-tools.mjs`、`borrowing.ts`：沿用线程级工具通道读取。

## persona 还值得借鉴什么

按收益与现有基础排序：

1. **最近打开的会话。** `web/src/lib/recent-chats.ts` 记录用户最近打开的 10 个会话，命令菜单展示 5 个，支持快速回到上一个。可接进现有搜索入口；顺序按用户打开时间，避免后台输出打乱人的切换路径。
2. **输入历史。** `web/src/views/chat/useSendHistory.ts` 和 `web/src/lib/send-history.ts` 支持上下键回取、Ctrl+R 搜索已发送输入。我们可增加手机点击入口；回填草稿由人发送，并保持引用和注释结构。
3. **网页元素批注。** `docs/web/preview.md` 的 Picking an element 使用 CDP 选择元素，携带 URL、CSS selector、文字、有限 HTML 和可用的组件来源，再转成注释块。适合延伸现有注释机制，让人直接指着网页说“改这里”；需要浏览器预览链路，实施量高于前两项。
4. **可撤销的只读会话分享。** `docs/web/web.md` 的 Sharing an Agent session 支持选消息、有效期、撤销，未来消息和工具详情默认不分享。适合把排查过程发给同事；需要独立的公开查看与权限边界，宜后续单独设计。

以上是候选建议，本轮没有顺带实现。
