# 自动接力与手动交接

交接关系保存在 hub 数据库的线程 `handover` 中，使用 `mode: continue | branch`。不改 agent 的原生会话或配置，不迁移旧数据。

- 手动交接一律 branch：无论来源运行中还是已停，新会话拿交接内容独立开始。弹窗无方式选择，来源不停、两个输入框各发给所看的会话。
  - 阅读时，来源没有再启动新轮、也没在运行，看来源的人往下滑会接上这条手动交接的会话（只读快照，分隔线写明「手动交接 · 来源 → 新会话」，下面是折叠的交接内容）；来源之后又启动了新轮、正在运行，或用户取消了这次接力，两边就是各自独立的会话，不再接上。输入框仍只发给所看的会话。
- 自动交接（额度接近上限/耗尽、协作成员自动接手）与额度报错卡片的一键接手显式使用 continue。只有这类接力合并正文，前段只读、输入发给最新一段。同实例换模型沿用原线程与模型分隔行。
- daemon 计算有效方式：缺 mode 的旧关系按 branch；continue 来源在交接后又启动新轮，也按 branch。用 `sourceSeq` 避免同毫秒事件先后歧义；无边界的 continue 按创建时间比较。读取不改写存储。响应中的 `automatic` 从原始 mode 推导，保留交接记录的触发方式；自动接力解除合并后也不会误标成手动。
- 侧边栏始终聚合所有交接关系：最新会话在上、「N 个会话」展开。只保留 agent 图标与状态点，链卡片保留前后叠放图标；分叉、工作树、交接与定时来源作为悬停文字，不占列表行。顶部交接记录保留来源导航，标出「自动接力 / 手动交接」。
- 正文加载与输入目标只沿有效 continue。中间关系改变时清除旧祖先缓存；侧边栏聚合不影响输入发送目标。

`POST /api/threads/:id/handover-thread` 默认 branch；自动调度及一键接手显式传 continue。非法方式返回 400。此接口不停止来源。线程列表与详情返回 daemon 计算的有效 mode，前端不自行推导运行事实。

## 验证范围

- daemon/API：运行中和已停的手动交接均 branch，不停止来源；模式写入与非法参数；自动 continue；旧记录与来源恢复的无迁移推导；自动来源标记保留；独立会话历史不隐藏正文。
- Web：所有模式及旧记录的侧边栏聚合，输入只沿自动接力，历史缓存失效。
- Chromium：四组合覆盖运行中/已停手动交接、独立发送、同一卡片展开与叠放图标、记录标签、自动接力前段只读，以及来源重新开轮解除接力。额度阈值实际触发、同实例换模型、取消、协作自动交接和一键接手沿用回归用例；工作树与分叉列表无额外图标、有悬停信息也有断言。
- 截图：`packages/e2e/shots/handover-mode2/`，`running-dialog-*`、`manual-sidebar-*`、`manual-history-*`、`idle-manual-*`、`continue-source-*`、`resumed-source-*`；后缀为 desktop/phone × light/dark。浏览器为真实无头 Chromium，手机为触控尺寸模拟；执行协议使用假 agent，未测实体手机和真实付费模型。
